# MUSUBIX4 autonomous development design / MUSUBIX4自律開発設計

## DES-AUTONOMOUS-DEVELOPMENT-001: Compatible CLI composition / 互換CLI構成
Responsibilities: Preserve the complete frozen MUSUBIX3 command tree and register compatibility-validated MUSUBIX4 lifecycle, collision-inventory amendment, and approval commands without changing inherited artifact semantics.
Interfaces: createProgram() returns the Commander command tree; registerHohCommands(program, services) exposes `musubix4 run`, `musubix4 resume <run-id>`, `musubix4 stop <run-id>`, the additive collision resolution `musubix4 status --run <run-id>`, and `musubix4 protected-set amend <run-id> --collision-inventory <path>`, while bare `musubix4 status` and inherited `approval record` retain their frozen behavior; automatic run-bound approval has no public record command.
Constraints: DES-AUTONOMOUS-DEVELOPMENT-014 owns candidate-surface derivation and collision validation; every registered HoH command, including collision-inventory amendment, must be present in the deterministic declared candidate surface; `.musubix/compatibility/command-collisions.json` is a protected MUSUBIX4-owned canonical JSON artifact containing exactly one entry for each candidate top-level command path and no entry absent from both frozen upstream and candidate surfaces, with DES-014 owning the exact upstream-only rule; immediately after candidate commit creation and before QA provisioning, static validation rejects malformed, duplicate, conflicting, missing candidate-path, and extra stale entries absent from both surfaces as `amendment-required`; QA separately checks runtime reachability of each pinned invocation; `status` resolves exactly as `{ inherited: "musubix4 status", kind: "additive-arguments", hoh: "musubix4 status --run <run-id>" }`; inherited forms and options retain frozen behavior and `musubix4 --version` identifies MUSUBIX4.

ADRs: ADR-0001 ADR-0002
Depends-On: DES-AUTONOMOUS-DEVELOPMENT-005 DES-AUTONOMOUS-DEVELOPMENT-012 DES-AUTONOMOUS-DEVELOPMENT-014

## DES-AUTONOMOUS-DEVELOPMENT-003: Public specification materializer / 公開仕様マテリアライザー
Responsibilities: Load the four supported specification sources, normalize and size-limit them, pin source identity, run the one-time deterministic versioned specification normalizer, and render the frozen result only as collision-free untrusted role data.
Interfaces: materializeSpecification(source, policy, runId, runStartNonce) returns PublicSpecification with sourceKind, locator, contentDigest, normalizedContent, and byte count; `ExecutableAcceptanceCase` is `{ id, entryId, kind: "command", commandSpec: { adapterId, argvTemplate, cwdKind: "candidate-root", inputBindings }, expected: { exitCodes, stdoutMatcher?, stderrMatcher?, diagnosticCodes?, outputKeys?, maxDurationMs?, maxOutputBytes? }, derivation: { normalizerVersion, sourceDigest, sourceOrdinal, caseOrdinal, mode: "declared" | "derived" } }`; normalizeSpecificationOnce(specification, normalizerVersion, maxRequirementEntries) returns a digest-pinned `PublicRequirementIndex` whose entries contain frozen entry ID, obligation text, one-or-more `ExecutableAcceptanceCase` values, and persisted `traceMapping: { generatedEntryId, sourceLocator, sourceOrdinal, sourceSpanDigest }`; executeAcceptanceCase(case, workspace, policy) delegates to DES-AUTONOMOUS-DEVELOPMENT-011 and returns a `CommandRecord`; frameRoleData(role, attemptNonce, index) returns bytes with a nonce-derived delimiter proven absent from the payload.
Constraints: Prompt text uses and resumes with the persisted locator `prompt:<run-id>:<run-start-nonce>:<content-sha256>`; Markdown and `.musubix` locators are canonical repository-relative paths plus content digest, and Issue locators pin repository, issue number, immutable fetched revision metadata, and content digest; normalization occurs exactly once before the first role and preserves declared IDs/cases; for prose-only behavior, split normalized source into stable ordered obligation units, derive the entry ID from source digest plus stable ordinal, then apply a versioned precedence table: parse an explicit fenced command, else parse an exact backticked candidate invocation, else bind the canonical `{ entryId, obligationDigest }` envelope to the configured acceptance executor; derive expected exit/output/diagnostic predicates from explicit acceptance text or versioned defaults, and fail before Planner with a typed non-executable-specification diagnostic when the selected adapter or deterministic predicate is unavailable; case IDs are digests of frozen entry ID, case ordinal, and canonical case body; persist the per-entry trace mapping beside the index and reuse it byte-identically across iterations; reject duplicate IDs, missing executable cases, more than 200 entries by default, or oversized input without truncation; QA and evidence consume only acceptance `CommandRecord` values produced through the contained command adapter, never role prose or source presence; role framing derives a candidate delimiter from role, invocation nonce, and index digest and deterministically increments a counter until absent from all content.

Constraints: Write redacted records atomically with same-directory temporary-file rename and fsync where available; store, add, and compare reservation, cumulative usage, and frozen budget as non-negative safe-integer nano-AIU, deriving the configured reservation and budget once through `Math.trunc(credits * 1000000000)` and dividing only in status/display serialization; transition sequence numbers are the ordering authority; persist nonce issuance and Reviewer spawn as ordered journal transitions and admit Reviewer evidence only when the spawn sequence follows the issuance sequence; key approval attempts by `(runId, stage, boundaryKind, amendmentEpisodeOrdinal?, amendmentAttemptOrdinal?)`, never let initial requirements drain amendment attempts, and preserve counters/nonces across interruption, stop, resume, re-entry, byte changes, and lease recovery; each evaluation uses a fresh single-use nonce and a successful decision consumes one attempt and closes only that key; reserve before every Reviewer or other role spawn and meter it identically, expose for status only the advisory worst-case remaining Reviewer invocation count derived from boundary, evaluation-attempt, and role-retry limits, gate each actual spawn only on its reservation, and stop with `budget-exhausted` before any unreserved spawn; persist blocker counters under their existing bounds; stale leases require dead-owner detection and an audit transition.
