# CHANGE-0010: baseline-oracle-regeneration

Requirements: REQ-AUTONOMOUS-DEVELOPMENT-001 REQ-AUTONOMOUS-DEVELOPMENT-002 REQ-AUTONOMOUS-DEVELOPMENT-013

## Intent

Restore HoH startup after an approved inherited-compatibility test update made
the frozen baseline manifest stale.

## Classification

Defect correction with a clarified baseline-governance requirement and design.
The existing contract already requires out-of-run regeneration, renewed
requirements and design approval, and a new HoH run whenever a
manifest-enumerated compatibility test changes. The clarification distinguishes
byte-identical upstream mirrors from locally maintained protected compatibility
evidence and requires dedicated compatibility-only test files.

## Impact

- Add a regression test that reproduces the version-2 manifest, artifact, and
  attestation bytes from the checked-in repository and verifies that every
  manifest-enumerated `*.test.ts` file contains only inherited-compatibility
  test IDs, has one such ID per test declaration, and pins the upstream commit
  plus procedure ID/version.
- Extract `TEST-CLI-COMPATIBILITY-001` from the churn-prone
  `tests/hoh-lifecycle.test.ts` into
  `tests/inherited-compatibility.test.ts`.
- Replace the frozen manifest entry for `tests/hoh-lifecycle.test.ts` with the
  dedicated inherited-compatibility test and update the historical trace and
  mandatory `inherited-compatibility` QA command to execute that complete file
  without a name filter, preventing a zero-test vacuous pass.
- Keep the dedicated compatibility test in the
  REQ-AUTONOMOUS-DEVELOPMENT-013 protected set while allowing ordinary HoH
  lifecycle tests to evolve without invalidating the upstream oracle.
- Bump the deterministic regeneration procedure from version `1` to `2`,
  regenerate the canonical artifact digest, and update the digest-pinned
  attestation entry.
- Preserve the pinned upstream repository and commit plus the byte-identical
  command surface and behavioral golden artifacts; regenerate the historical
  trace with the dedicated compatibility-test path.
- Run `trace build` so the trace cache and every feature trace copy record
  `TEST-CLI-COMPATIBILITY-001` at its new authoritative path and current source
  digest.
- Record renewed requirements and design approvals before implementation, then
  obtain a new release approval before the replacement HoH run.
- Restore `.musubix/hoh.json` before final validation and the replacement HoH
  release run.

## Regeneration procedure

Procedure `musubix3-canonical-oracle` version `2` deterministically:

1. Retains, in manifest order,
   `tests/fixtures/musubix3-cli-surface.json`,
   `baseline-specs/oracle/goldens/status.json`,
   `tests/inherited-compatibility.test.ts`, and
   `baseline-specs/oracle/historical-trace.json`.
2. Computes each artifact SHA-256 from its checked-in bytes.
3. Computes `artifactDigest` as SHA-256 of the compact JSON encoding of the
   ordered `{ path, sha256 }` array.
4. Writes the attestation with `schemaVersion` 1, the unchanged upstream
   repository and commit, procedure version `2`, and the `artifactDigest` from
   step 3.
5. Computes the attestation file SHA-256 and records it in the manifest.

The exact generated bytes are verified by
`TEST-AUTONOMOUS-ORACLE-005` against the checked-in repository.

## Bootstrap note

The v0.1.1 HoH run was rejected before run creation with
`Baseline artifact digest mismatch: tests/hoh-lifecycle.test.ts`. The user
approved temporarily removing `.musubix/hoh.json` as a bootstrap action so the
protected baseline can be regenerated outside an autonomous run, as
REQ-AUTONOMOUS-DEVELOPMENT-001 requires.
