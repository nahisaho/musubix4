# ADR-0006: Role-specific least privilege at harness and subprocess boundaries

## Context / 背景

Copilot tool permissions alone cannot constrain arbitrary subprocess behavior,
and public specifications may contain hostile instructions.

## Decision / 決定

Generate explicit per-role Copilot tool, path, URL, MCP, and instruction
allowlists. Spawn subprocesses without a shell inside a contained working
directory using an environment allowlist, secret stripping, bounded output,
timeouts, and configured network policy. Treat specification and evidence as
escaped, delimited untrusted data. Apply redaction again at every persistence
boundary for journals, command records, and normalized evidence. Derive one
effective policy per role invocation from a versioned role default plus
explicit additions, and record the policy digest and residual-risk diff. The
versioned policy roles are Planner, Developer, QA, and Deployment.

Treat `baseline-specs/**`,
`.musubix/compatibility/command-collisions.json`, and manifest-enumerated
compatibility tests/fixtures as one protected set. Verify its effective digest
at run start, every role boundary, QA snapshot creation, and candidate
acceptance. In-run amendment is limited to an explicit `musubix4 protected-set
amend <run-id> --collision-inventory <path>` request. Baseline manifests,
`baseline-specs/**`, manifest-enumerated compatibility tests/fixtures, public
specification, and normalized requirement-index changes require out-of-run
regeneration or update, renewed approvals, and a new run. Unrequested mismatches
fail rather than entering amendment handling.

The registered amendment CLI is included in the candidate command surface and
collision validation. After a new current requirements approval pins the
collision-inventory amendment manifest, each attempt verifies the proposed
digest before commit, creates a provisional commit differing only at the
inventory, and verifies its digest and static declared surface afterward. The
provisional commit becomes the candidate only after all checks pass; the same
transition atomically re-pins the recomputed effective protected-set digest and
binds it to the approval. Any pre-commit, post-commit, journal, or re-pin failure
discards the provisional commit, retains the original candidate and prior pin,
increments the durable episode-scoped failure count, and returns to
`amendment-required`. No role or QA observes provisional state.

## Rejected alternatives / 却下案

- `--allow-all` for every role: rejected as incompatible with the selected
  least-privilege policy.
- Prompt-only safety instructions: rejected because they are not an enforceable
  security boundary.
- Automatically accept protected-file edits from Developer: rejected because
  the candidate could rewrite its own oracle or collision policy.

## Consequences / 結果

Some project commands require explicit configuration. The runtime records
residual risks for capabilities deliberately added beyond role defaults.
Intentional collision-inventory maintenance pauses the run and requires
reapproval; other protected-set maintenance is out of run, and unexpected
mutation is fail-closed.
