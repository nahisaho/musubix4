# ADR-0015: Separate product version checks from the frozen compatibility oracle

## Status
Accepted

## Context
The manifest-enumerated inherited compatibility test validates the frozen
MUSUBIX3 command and option surface, but it also asserted that the evolving
musubix4 executable version was exactly `0.1.0`. Updating any release version
therefore either failed the test or required changing a protected oracle
artifact during an autonomous run. Repeated v0.1.1 and v0.1.2 candidates
demonstrated this conflict.

The current musubix4 version is already verified independently by
`tests/release-version-consistency.test.ts` against package, workspace,
lockfile, plugin, documentation, and executable surfaces. The separate package
archive verifier covers the packed distribution surfaces.

## Decision
Remove the exact product-version assertion from the frozen inherited
compatibility test while retaining its executable-name and complete inherited
command/option checks. Add a non-frozen oracle-governance regression that
selects a non-empty set of manifest-enumerated test paths and parses them as
TypeScript, excluding comments and type-only nodes. It rejects value-level
identifier/binding/property tokens whose decoded value is an exact
case-sensitive `version` and statically constant strings containing a
`--version` or `-V` token bounded by string boundaries,
ASCII whitespace, comma, equals sign, or colon. The non-frozen governance test
is not manifest-enumerated.
The inherited version option remains exercised only through the frozen
data-driven surface snapshot. Findings use
`BASELINE_COMPATIBILITY_VERSION_COUPLING` with repository-relative POSIX path
and 1-based line/UTF-16 column at the offending token.

Regenerate the locally maintained protected compatibility test through
procedure `musubix3-canonical-oracle` version `3`. Recompute its artifact
SHA-256, the ordered aggregate artifact digest, the regeneration attestation
SHA-256, and the manifest bindings. Preserve all upstream-mirrored artifact
bytes, the pinned upstream commit, the historical trace, and artifact order.
Perform the protected edit and regeneration as one out-of-run maintainer
operation before starting the replacement HoH run. The same operation updates
the non-frozen procedure-version/governance expectations, relocates
source-layout version-value coverage into the non-frozen release-version test,
and refreshes trace and quality fingerprints invalidated by the protected edit.

Set the HoH command timeout to 300000 ms so the unchanged mandatory full test
command, measured above the previous 120000 ms ceiling, can complete.

## Rejected alternatives
- **Keep the `0.1.0` assertion and change `createProgram()` to report it.**
  This would make the executable disagree with the package and published
  version.
- **Rewrite the frozen test inside each release candidate.** Autonomous runs
  are prohibited from amending manifest-enumerated baseline artifacts.
- **Remove the inherited compatibility test from the manifest.** This would
  discard protected command-surface evidence instead of correcting its scope.
- **Skip or narrow the full HoH test command.** This would weaken release
  evidence rather than provide sufficient execution time.

## Consequences
- Product releases can advance without changing the frozen compatibility test.
- A one-time out-of-run baseline regeneration and renewed approvals are
  required.
- Current-version verification remains fully enforced by the dedicated
  non-frozen release test and archive verifier.
- HoH candidate checks retain all configured commands but may run longer.
