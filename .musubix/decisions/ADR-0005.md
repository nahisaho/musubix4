# ADR-0005: Internal Git refs and disposable worktrees

## Context / 背景

Each role and iteration needs versioned state, QA must inspect the exact
candidate independently, and the user's branch and uncommitted work must not be
rewritten.

## Decision / 決定

Create an isolated run workspace, persist stage commits under
`refs/musubix4/runs/<run-id>/...`, and create disposable QA worktrees from exact
candidate commits. Candidate snapshots contain tracked files plus explicitly
configured extra paths; run telemetry stays outside source snapshots. Capture
dirty user state with a temporary Git index and isolated workspace, never by
stashing, resetting, or committing the user's worktree. Verify the candidate
tree digest after QA and reconcile orphan worktrees during recovery. The
durable run journal is the sole authority for the last preservation-verified
candidate. Its internal Git ref is an idempotent, re-derivable projection:
recovery recreates a missing matching ref and prunes a conflicting or orphan
ref before rollback.

At snapshot creation, record the candidate lockfile path and SHA-256 when
exactly one supported lockfile exists or frozen configuration explicitly
selects one, or record that no lockfile exists. Multiple supported lockfiles
without explicit selection are a typed configuration failure. Before QA
provisioning, verify the worktree lockfile against that record. Provision with
the configured bounded adapter into declared writable disposable dependency
and cache paths, with lifecycle scripts disabled unless explicitly approved.
No-lockfile projects skip provisioning with a recorded reason but still run all
configured checks. Tracked source remains non-writable.

For a requirements-approved collision-inventory amendment, create a provisional
internal commit whose only delta from the retained original candidate is
`.musubix/compatibility/command-collisions.json`. It is not a candidate, QA
input, or preservation unit until pre/post approved-digest checks and static
declared-surface validation succeed. Any validation failure discards the
provisional ref and retains the original candidate. Successful promotion
re-pins the effective protected digest before exactly one QA provisioning and
evaluation pass.

## Rejected alternatives / 却下案

- Commit directly to the user's branch: rejected because autonomous iterations
  would pollute user history.
- Plain directory copies only: rejected because identity, ancestry, and
  rollback evidence would be weaker.
- Provision in the Developer workspace or tracked QA tree: rejected because QA
  could mutate the accepted candidate or the user's working state.

## Consequences / 結果

Git is required for HoH runs. Projects must either run without provisioning or
provide an approved lockfile adapter and writable disposable path. Cleanup must
remove worktrees and disposable dependencies without deleting internal evidence
refs.
