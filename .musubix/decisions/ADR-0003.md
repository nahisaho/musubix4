# ADR-0003: Durable finite-state machine with append-only transitions

## Context / 背景

HoH runs span many independent processes and may stop during any role. Resume
must neither repeat completed work nor skip incomplete work.

## Decision / 決定

Represent each run as an explicit finite-state machine. Persist immutable
transition records with monotonic sequence numbers, atomically update a compact
current-state record, and protect mutation with a reclaimable single-writer
lease. A step executes at most one incomplete transition. Approval-paused
states persist their nonce and release the lease so a separate approval command
can acquire it and append the decision. Collision-inventory amendments use the
same pause discipline. Persist a per-run amendment episode count and a failure
count scoped to the current `amendment-required` episode. The episode count
increments on entry, survives interruption/stop/resume, and defaults to a
maximum of three; entry into a fourth episode is terminal. The failure count
also survives repeated operator requests and approvals, permits the initial
attempt plus two retries by default, and resets only after a successful
amendment leaves the state. Active duration is a journal-wide fold of executing, non-paused state
intervals, excluding approval, amendment, stopped, and between-process time.
Persist blocker-repair state as a target digest over iteration, a monotonic
repair-episode ordinal, and the first blocked candidate plus a result count.
The initial blocked result and two default repair outcomes share that target
even if their diagnostic codes or offending paths differ, and survive
interruption. Success resets the state; exhaustion records a completed
non-improving iteration, rolls back to the preservation-verified candidate or
run base, and lets the normal iteration and stagnation limits bound subsequent
episodes.
For a crash leaving an unmatched role interval, recovery closes it at the
earlier of recovery observation and role-start plus the configured role timeout,
so one crash cannot charge more than that timeout. The accumulated total is
persisted at each transition and recomputed from the full journal on recovery.

## Rejected alternatives / 却下案

- One mutable JSON document: rejected because partial writes and ambiguous
  recovery would lose transition history.
- Resident daemon as the source of truth: rejected because v1 is a resumable
  foreground CLI and must survive process loss.

## Consequences / 結果

State handling is more explicit and testable. Every new transition requires a
schema and recovery rule; status must expose both amendment counters, required
operator action, offending inventory paths, and terminal reason; active-time
boundaries require persisted transition timestamps plus monotonic sequence
authority.
