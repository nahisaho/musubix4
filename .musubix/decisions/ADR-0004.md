# ADR-0004: Separate Copilot invocations with schema-constrained outputs

## Context / 背景

Harness-of-Harness requires Planner, Developer, and QA independence while using
one fixed harness-model configuration.

## Decision / 決定

Invoke GitHub Copilot CLI non-interactively in a separate session for every
role attempt. Compose prompts from fixed role modules and delimited runtime
data, request structured output, validate it against versioned local schemas,
and retry invalid output without advancing state. A premature Planner readiness
proposal is invalid output. Before each invocation reserve
`roleInvocationReservedCredits`, defaulting to 1 positive AI credit. Charge the
full parsed non-negative usage, including amounts above the reservation; record
an overrun and exhaust the budget immediately when applicable. Timeout,
transport failure, interruption, missing/unparseable usage, and invalid output
are durably abandoned before retry and consume the full reservation when usable
usage is unavailable. Enforce the configured role timeout on every attempt.
Maintain one persisted retry counter for each logical role step. Invalid
output, premature readiness, timeout, and transport failures all increment that
same counter. With the default two retries, the third failed attempt is
terminal; failure categories do not receive separate retry budgets.

Freeze the specification through one deterministic versioned normalizer before
the first role. It emits at most 200 entries by default, each with a stable ID,
obligation text, and executable cases. Frame frozen specification, evidence,
and development-document data with a per-role-attempt nonce-derived delimiter,
deterministically selecting another delimiter if the candidate occurs in data.

## Rejected alternatives / 却下案

- One continuing Copilot conversation: rejected because role context and
  previous development documents would leak across boundaries.
- Free-form Markdown only: rejected because deterministic orchestration cannot
  safely distinguish valid results from success-shaped prose.
- Charge zero when usage is unavailable: rejected because failures could evade
  the positive budget and make retry cost unbounded.
- Escape one fixed delimiter: rejected because hostile input can contain it and
  blur the role instruction/data boundary.

## Consequences / 結果

Role calls incur additional model cost but are independently auditable,
retryable, budget-conservative, timeout-bounded, and permission-scoped. The
one-time normalizer rejects oversized, over-count, or non-executable
specifications before any model cost is incurred.
