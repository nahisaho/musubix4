# ADR-0008: Stable claim-evidence model for readiness and improvement

## Context / 背景

The loop needs deterministic readiness, regression, preservation, and
stagnation decisions across independently generated QA reports.

## Decision / 決定

Create exactly one claim for every applicable frozen requirement-entry and
quality-dimension pair. Derive a stable ID from the frozen entry ID plus the
canonical dimension name, require one of verified, gap, or
insufficient-evidence with public citations, and compute readiness and
improvement only from normalized records. For non-`.musubix` inputs, derive an
immutable run requirement set from ordered source units; generated IDs combine
the frozen source digest with a stable ordinal, and a persisted per-entry trace
mapping records source locator, ordinal, and source-span digest.

Define one deterministic universal rubric: functional correctness requires
executable acceptance cases; completeness requires executing evidence for every
obligation; regression safety attributes the run-level prior-verification and
inherited-compatibility result to every requirement; usability requires
affected help/candidate-surface visibility and actionable typed failures;
security requires no undeclared capability or named-secret exposure;
performance requires configured time/output and stricter stated bounds; and
maintainability requires static-validation, build, trace, dependency-cycle, and
structured-contract checks for traced artifacts. Build, focused test,
static-validation, trace, dependency-cycle, structured-contract, and inherited
compatibility are the seven mandatory checks. Before QA, static declared-surface
and inventory validation is a pre-claim gate: amendment-required failures assign
no claims. QA re-extracts the declared surface with the same versioned contract,
requires an identical digest, and executes every pinned invocation after
provisioning. Incorrect or unreachable present resolutions create affected
usability gaps and inherited-compatibility regression gaps when applicable.
Only the evidence engine can accept a promoted candidate or authorize readiness;
Planner readiness and QA prose are proposals.

Planner handoff capacity is `max(200, current non-verified claim count)`.
Non-verified claims are always listed first and never truncated; only trailing
verified summaries may be omitted. Improvement, regression, and readiness use
the complete claim set.

## Rejected alternatives / 却下案

- Use the QA agent's overall prose verdict: rejected because it is unstable and
  cannot support exact boundary tests.
- Count passed tests only: rejected because usability, completeness, security,
  and other selected dimensions require broader observable evidence.
- Let Planner or QA declare readiness: rejected because role prose is not the
  deterministic authority over complete normalized claims.

## Consequences / 結果

QA schemas are more verbose, but planner handoff, rollback, and stopping become
deterministic and auditable. Large unresolved sets increase Planner context,
but no unresolved claim is hidden by a fixed summary limit.
